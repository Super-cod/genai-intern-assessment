# Project 1 — Intelligent Document Retrieval & Question Answering (RAG)

Upload PDF/TXT documents and ask questions in a chat. Answers are **grounded in the documents with citations**. The system **refuses instead of guessing** when the documents don't contain the answer, and it **detects conflicting documents** and tells you which one is newer.

Runs fully locally (Ollama). The LLM sits behind a provider-agnostic API layer, so switching to OpenAI-compatible or Anthropic APIs is a single setting.

## Features

* Multi-file upload of PDF and TXT, validated by extension **and** magic bytes, with size limits and per-file error reporting
* Preprocessing: Unicode normalisation, de-hyphenation, running header/footer and page-number removal, effective-date extraction
* Structure-aware chunking: section boundaries, sentence overlap, contextual "Document > Section" headers
* Hybrid retrieval: FAISS dense (EmbeddingGemma) plus BM25, fused with weighted reciprocal rank fusion
* Relevance gate: clearly off-topic questions are refused without calling the LLM
* Grounded generation with structured JSON output and `[S1]`-style citations (document, page, section, snippet)
* Verification: invented citation labels, unsupported numbers and low lexical grounding make the system refuse
* Duplicate handling (exact and near-duplicate) and **conflict handling** (newer document wins and the conflict is reported)
* Conversational follow-ups via query rewriting ("How long does it take to charge **it**?")
* Structured error responses (409 no documents, 413, 415, 422, 502 LLM output, 503 LLM down)
* Minimal web UI plus Swagger docs

## Setup

Requirements: Python 3.10+ and [Ollama](https://ollama.com).

```bash
ollama pull qwen2.5:7b
ollama pull embeddinggemma

cd ps1-rag-qa
python -m venv .venv && .venv\Scripts\activate     # (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env                              # optional: change models / provider
python sample_docs/generate_samples.py              # (sample docs are already included)
```

## Run

```bash
uvicorn app.api:app --port 8000
```

* Web UI: <http://localhost:8000>. Upload the files in `sample_docs/`, then ask questions.
* Swagger: <http://localhost:8000/docs>

API examples:

```bash
curl -F "files=@sample_docs/employee_handbook_2024.pdf" -F "files=@sample_docs/leave_policy_update_2025.txt" http://localhost:8000/documents
curl -X POST http://localhost:8000/query -H "Content-Type: application/json" -d "{\"question\": \"How many days of annual leave do I get?\"}"
# follow-up: pass back the session_id from the previous response
curl -X POST http://localhost:8000/query -H "Content-Type: application/json" -d "{\"question\": \"Can I carry any of it over?\", \"session_id\": \"<id>\"}"
```

Response shape (abridged):

```json
{
  "status": "answered",
  "answer": "Full-time employees are entitled to 24 days of paid annual leave per calendar year, as of January 1, 2025 [S1].",
  "citations": [{"label": "S1", "doc_name": "leave_policy_update_2025.txt", "section": "Annual Leave Entitlement", "snippet": "..."}],
  "conflict_note": "Sources disagree: leave_policy_update_2025.txt (effective 2025-01-01) [S1] differs from older employee_handbook_2024.pdf (effective 2024-01-01) [S4]. The newer document takes precedence.",
  "grounding_score": 1.0,
  "standalone_question": "How many days of annual leave do I get?",
  "retrieved": [{"label": "S1", "doc_name": "...", "dense_score": 0.56, "bm25_score": 6.8, "fused_score": 0.021}],
  "timings_ms": {"rewrite": 0.1, "retrieval": 420.0, "generation": 9800.0, "total": 10220.0}
}
```

`status` is one of `answered`, `not_found` (no relevant passages; LLM not called), `insufficient_context` (the model judged the passages insufficient) or `unsupported` (the draft failed verification).

```bash

set LLM_PROVIDER=openai & set LLM_MODEL=gpt-4o-mini & set LLM_BASE_URL=https://api.openai.com/v1 & set LLM_API_KEY=sk-...
# Anthropic Claude (pip install anthropic)
set LLM_PROVIDER=anthropic & set LLM_MODEL=claude-opus-5-5 & set ANTHROPIC_API_KEY=...
```

## Project structure

```
app/
  api.py                 FastAPI routes + error mapping
  pipeline.py            orchestration (ingest / query) + timings
  config.py, errors.py, schemas.py
  llm/                   provider-agnostic LLM + embedding clients (Ollama, OpenAI-compatible, Anthropic)
  ingestion/             loaders (PDF/TXT), cleaner (preprocessing), chunker
  retrieval/             FAISS+BM25 index (dedup, persistence), retriever (hybrid, gate)
  generation/            prompts, answerer (verification), conflicts, conversation memory
  static/index.html      web UI
sample_docs/             corpus + edge cases + generator
eval/                    queries.json, run_eval.py, results/
tests/                   unit + API tests
docs/                    ARCHITECTURE.md, DECISIONS.md, EVALUATION.md
```

## Known limitations

See [EVALUATION.md §6](docs/EVALUATION.md#6-limitations). In short: a small evaluation set, lexical (not semantic) grounding checks, numeric-only conflict detection, no OCR, and 7–17 s latency on a 4 GB laptop GPU.
